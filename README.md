# clicked-through

**A design-research study of what technical people do when a security warning has
no answer they can give.**

76 coded items drawn from 372 Hacker News threads, 2021–2026. Corpus, sampling log,
screening decisions and codebook are all in this repository, so the finding can be
argued with rather than taken on trust.

**→ [Read the report](https://uxrhimanshu.github.io/clicked-through/)** — the argument,
with all 76 items filterable by code and each linked back to the thread it came from.

---

## The finding, in thirty seconds

I set out to study why competent people click through security warnings, expecting
to find a risk calculus: *I know what this says, I'm proceeding anyway.*

That is in the corpus, but it is the smallest thing in it — six items, no sustained
discussion. What dominates instead is people meeting **a warning that cannot be
obeyed**.

A browser tells you a certificate cannot be trusted. You are connecting to a
printer on your own network. There is no compliant answer to give, because the
public-CA path the warning assumes does not exist for a device on a LAN address.
The warning has one meaning available — *someone may be attacking you* — and the
situation has another, and nothing in the interface can hold both.

> It's becoming increasingly troublesome these days to run a service on insecure
> HTTP. Doubly so to run a service with a self signed certificate, which gets
> treated as a sign of evil intent by all browsers.

Three things follow, and practitioners describe all three themselves:

**The organisation forbids the compliant path, so the insecure one becomes
policy.** One engineer could only get proper certificates by filing a ticket and
waiting days; obtaining them from a real CA was "absolutely forbidden" — so
self-signed certificates went into production. The risk-averse process produced the
less secure outcome.

**The goal quietly becomes the silence of the indicator.** One supplier ships the
same wildcard certificate *and private key* to thousands of machines across
hundreds of companies. It is worse than what it replaced. But, in the poster's
words: "it gets rid of the red X in a browser so tick."

**Everyone can see the habituation coming.** "It reduces your security because your
users will inevitably learn to ignore certificate errors." Or, on Windows RDP,
where self-signed certificates expire every six months: "users eventually learn to
just ignore these warnings." A default nobody chose sets how often an unavoidable
warning fires, and the frequency decides what it comes to mean.

The same pattern appears in a control that looks nothing like a certificate dialog.
Phishing training tells people to check the domain — while the employer routes
legitimate work through link-shorteners and unfamiliar third-party domains a
hundred times a day. One person clicked a suspicious link deliberately to
investigate it, entered nothing, and was recorded as having failed the audit.

**In every case the behaviour that gets called user error is the only behaviour the
situation leaves available.**

## Why you can check this

Most netnographic work asks you to believe that the quotes are representative.
Here, every step is a file:

| | |
|---|---|
| [`FINDINGS.md`](FINDINGS.md) | the argument, with quotes |
| [`METHOD.md`](METHOD.md) | what this design cannot support — **read before the findings** |
| [`corpus/SAMPLING.md`](corpus/SAMPLING.md) | generated by the collection tool, committed unedited |
| [`screening.csv`](screening.csv) | a decision and a declared reason for all 1,785 retrieved items |
| [`codebook.md`](codebook.md) | code definitions, inclusion and exclusion criteria |
| [`coded.csv`](coded.csv) | item → code, joins to the corpus on `item_id` |
| [`corpus-lexical-screen/`](corpus-lexical-screen/) | a screening approach that **failed**, kept so the failure is inspectable |
| [`index.html`](https://uxrhimanshu.github.io/clicked-through/) | the report, with the evidence explorable |

```sh
python3 check_quotes.py   # every quote, in FINDINGS.md *and* on the page, is in the corpus
python3 screen.py report  # every retrieved item has a decision; no invented reasons
python3 corpus_stats.py   # counts, and code spread across threads
python3 build_site.py     # regenerate the report's data from the CSVs
```

The page never carries hand-typed numbers. `build_site.py` writes its counts, both
charts and all 76 items from `coded.csv` and the sampling log, so revising the codebook
means re-running one script rather than editing HTML and hoping it still matches.

`check_quotes.py` verifies that the quoted words appear in the item they are
attributed to — not just that the id resolves. It is the check a hostile reader
runs first, so it may as well be one command.

## Three things I got wrong, kept in the repository

**A large corpus can be empty.** The first harvest returned 1,786 items and was
mostly noise: search matches whole threads, so a product announcement that used the
phrase "security warning" once arrived with ninety replies about pricing attached.

**Tightening the query does not fix it.** The second harvest, with narrower terms,
returned 1,791 items and the same problem.

**A keyword screen is precise about words and blind to meaning.** The third attempt
filtered to items containing a query phrase. It cut 2,350 items to 103 — and kept a
link post titled "Preventing Alert Fatigue" with no body text, and a Kubernetes
certificate-pinning argument, while missing every account phrased in words the list
had not anticipated. That corpus is in `corpus-lexical-screen/`.

The phenomenon is semantic and the retrieval is lexical. No amount of query tuning
closes that gap; something has to read the items. So the screen that was actually
used is a read-through with a recorded decision per item, which is why
`screening.csv` exists.

**The original question had to change.** I started from "why do people dismiss
security warnings" and the corpus could support ten items on it. The question was
reframed to what the data could answer, before coding, and that is disclosed here
rather than presented as the plan all along.

## Honest limits

`METHOD.md` has the full list. The three that matter most:

- **No frequencies.** Nothing here supports "X% of engineers do Y". A corpus
  assembled by phrase search from a self-selected forum has no denominator, and
  the code counts are counts of items in this corpus, nothing more.
- **First-pass coding was LLM-proposed**, then reviewed by me. Disclosed in
  `METHOD.md`, and no inter-rater statistic is reported because none would mean
  anything. It would be absurd to write about people taking a defensible-looking
  shortcut and then quietly take one.
- **One community.** Hacker News is English-speaking, technical, US-weighted and
  unusually confident of its own competence. Every finding is a finding about that
  population.

## See also

quantitative counterpart: 10,042 public security incidents, asking where
interfaces, defaults and warnings set people up to fail. It establishes that

rather than reasoning. This study is the other half, and the two converge without
having been designed to.
